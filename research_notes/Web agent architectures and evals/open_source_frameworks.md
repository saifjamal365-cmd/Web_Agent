# Open-source and developer-platform web agent frameworks (state as of Nov 2026)

Scope: Browser Use (0.x and 1.0), Stagehand v3 (Browserbase), Skyvern 2.0, Agent-E, Notte, Playwright MCP, HyperAgent/Hyperbrowser, Steel. Research date 2026-11-22. Note: several frameworks changed a lot in 2026. Browser Use 1.0 dropped its built-in action registry and DOM dumps, and Notte 1.10 removed its agent loop. "Current" and "legacy" are labelled throughout.

## What tool set does each framework expose, especially for extracting lists of items (products) and comparing them?

### Takeaway
The richest list-extraction tool sets are Browser Use 0.x (`extract` with an `output_schema`, plus zero-LLM-cost `search_page` and `find_elements`), Stagehand (`extract` with a Zod/Pydantic schema) and Skyvern (Data Extraction block plus `page.extract`). Browser Use 1.0 replaced all its actions with a Python REPL over raw CDP, so the agent writes its own parsing code. Playwright MCP has no LLM extraction tool. The agent reads the accessibility snapshot, or uses `browser_find` / `browser_evaluate`.

### Cited Findings
**Browser Use 0.x (legacy, last checked tag 0.12.0; install with `pip install 'browser-use<1'`)**
- Full action registry in `browser_use/tools/service.py`: `done`, `search` (duckduckgo/google/bing), `navigate` (`url`, `new_tab`), `go_back`, `wait` (default 3s, capped at 30s), `click` (by `index`; coordinate mode `coordinate_x`/`coordinate_y` only for some models; clicking a `<select>` redirects to `dropdown_options`), `input` (`index`, `text`, `clear`), `upload_file` (`index`, `path`), `switch` / `close` (`tab_id`), `extract`, `search_page`, `find_elements`, `scroll` (`down`, `pages` 0.5–10, optional `index`), `send_keys`, `find_text` (scroll to text), `screenshot`, `save_as_pdf`, `dropdown_options`, `select_dropdown` (`index`, `text`), `write_file`, `replace_file`, `read_file`, `read_long_content`, `evaluate` (JS via CDP, output capped at 20,000 chars) — [browser-use tools/service.py @0.12.0](https://raw.githubusercontent.com/browser-use/browser-use/0.12.0/browser_use/tools/service.py)
- `extract` is an LLM call over page markdown. Params: `query`, `extract_links`, `start_from_char` (to resume after truncation), `output_schema` (falls back to free text if the schema is invalid). It works in chunks of up to 100,000 chars, times out at 120s, and saves long results to a file — [service.py @0.12.0](https://raw.githubusercontent.com/browser-use/browser-use/0.12.0/browser_use/tools/service.py)
- `search_page` (`pattern`, `regex`, `case_sensitive`, `context_chars`, `css_scope`, `max_results`) is a "zero-LLM-cost" text search that returns a total and a has-more flag. `find_elements` (`selector`, `attributes`, `max_results`, `include_text`) is a zero-LLM-cost CSS query; text is cut to 300 chars and attributes to 500 chars — [service.py @0.12.0](https://raw.githubusercontent.com/browser-use/browser-use/0.12.0/browser_use/tools/service.py)
- `done` takes `text` (or a typed `data` output model), `success` and `files_to_display` — [service.py @0.12.0](https://raw.githubusercontent.com/browser-use/browser-use/0.12.0/browser_use/tools/service.py)
- Prompt guidance for lists: "Use `find_elements` to count items such as table rows or product cards." Use `extract` only when the data is not already in `<browser_state>`. Never repeat the same `extract` query on the same page. Every fact must come from a visited page — [system_prompt.md @0.12.0](https://raw.githubusercontent.com/browser-use/browser-use/0.12.0/browser_use/agent/system_prompts/system_prompt.md)
- A `CodeAgentTools` variant excludes `extract`, `find_text`, `screenshot`, `search`, `write_file`, `read_file` and `replace_file` by default — [service.py @0.12.0](https://raw.githubusercontent.com/browser-use/browser-use/0.12.0/browser_use/tools/service.py)

**Browser Use 1.0 (current)**
- "0.x had built-in actions such as `click`, `extract` and `scroll`. 1.0 has none." Instead, the agent writes Python against helpers: `new_tab`, `goto_url`, `js`, `cdp`, `click_at_xy`, `type_text`, `press_key`, `scroll`, `screenshot`, `upload_file`, `http_get`, `checkpoint`, `show_image`. The reserved names are `python`, `finish` and `finish_from_repl`. Custom tools use `@tools.action` — [Browser Use docs: available tools](https://docs.browser-use.com/customize/tools/available)
- 1.0 "writes Python against raw CDP in a persistent REPL, on Pydantic AI". The "Ultrafast" mode (`mode='ultrafast'`, which replaces `flash_mode`) "acts on accessibility-tree ids with the bu helpers" — [llms.txt index](https://docs.browser-use.com/llms.txt); [Migrating from 0.x](https://docs.browser-use.com/open-source/migrating.md)
- Browser Use's March 2026 Online-Mind2Web post names "adding Python code execution to the harness" for parsing HTML and extracting data as "the biggest improvement" — [Browser Use: Online-Mind2Web post](https://browser-use.com/posts/online-mind2web-benchmark)

**Stagehand v3 (Browserbase)**
- Primitives: `act` (natural-language action), `observe` (returns candidate elements and selectors, so the model never sees credentials), `extract` (schema-validated data with Zod/Pydantic/Go types), and `agent` — [Stagehand README](https://github.com/browserbase/stagehand)
- `agent()` tools. DOM mode (the default; any LLM; TypeScript only): `act`, `fillForm`, `ariaTree`, `extract`, `goto`, `scroll`, `keys`, `navback`, `screenshot`, `think`, `wait`, `search`. Hybrid mode (`mode: "hybrid"`, needs `experimental: true`) adds `click`, `type`, `dragAndDrop`, `clickAndHold` and `fillFormVision`. CUA mode (`mode: "cua"`) uses Google/OpenAI/Anthropic/Microsoft computer-use models with coordinates, and does not support variables, streaming, callbacks or structured output. `search` needs `useSearch: true` and a Browserbase key. Custom tools use `tool`, and built-ins can be removed with `excludeTools` — [Stagehand docs: agent](https://docs.stagehand.dev/v3/basics/agent)

**Skyvern**
- Workflow blocks: Browser Task, Browser Action, Data Extraction, Validation, For Loops, File parsing, Sending emails, Text Prompts, HTTP Request, Custom Code, and file upload to block storage. File download is a feature, and conditionals were "coming soon". The Playwright-compatible SDK adds `page.act`, `page.extract`, `page.validate`, `page.prompt` and `page.agent`. Playwright actions accept a `prompt` parameter, with a mode that tries the selector first and falls back to AI — [Skyvern README](https://github.com/Skyvern-AI/skyvern)
- A task is a URL plus a prompt, with an optional data schema and error codes. Workflows chain tasks — [Skyvern README](https://github.com/Skyvern-AI/skyvern)

**Agent-E (Emergence AI, July 2024 — older, research code)**
- Skills are Python functions exposed for function calling. Sensing: get DOM with a content type (`text_only`, `input_fields`, `all_fields`). Acting: click, enter text, open URL, press keys. Each action skill returns "change observation" feedback. The exact function names are only in Figure 4 of the paper and were not legible in the text — [Agent-E arXiv 2407.13032](https://arxiv.org/html/2407.13032)

**Notte (current 1.10+)**
- Session API: `session.observe()` (returns an action space and a description), `session.execute()`, `session.act()` (one observe-decide-execute step), and `session.scrape(only_main_content=True)` (markdown). Cloud scrape takes `instructions` plus a Pydantic `response_format`, and `scrape_links`. Named actions include `goto`, `captcha_solve`, `form_fill` and `upload_file`. Credentials live in a vault (Notte vaults, `AacVault`, `BitwardenVault`), so the LLM only sees placeholders — [Notte README](https://github.com/nottelabs/notte)
- In 1.10, Notte removed `notte.Agent`, `client.Agent`, `AgentFallback` and Workflows. Functions (a deployed Python `run`) remain — [Notte README](https://github.com/nottelabs/notte)

**Playwright MCP (Microsoft)**
- Core tools: `browser_click`, `browser_drag`, `browser_drop`, `browser_evaluate`, `browser_file_upload`, `browser_fill_form`, `browser_handle_dialog`, `browser_hover`, `browser_press_key`, `browser_select_option`, `browser_type`, `browser_wait_for`, `browser_navigate`, `browser_navigate_back`, `browser_resize`, `browser_emulate_media`, `browser_close`, `browser_snapshot`, `browser_find`, `browser_take_screenshot`, `browser_console_messages`, `browser_network_requests`, `browser_network_request`, `browser_run_code_unsafe`, and `browser_tabs` — [Playwright MCP README](https://github.com/microsoft/playwright-mcp)
- Opt-in via `--caps`: `vision` (`browser_mouse_click_xy`, `browser_mouse_move_xy`, `browser_mouse_drag_xy`, `browser_mouse_down`, `browser_mouse_up`, `browser_mouse_wheel`), `pdf` (`browser_pdf_save`), `testing` (`browser_generate_locator`, `browser_verify_element_visible`, `browser_verify_list_visible`, `browser_verify_text_visible`, `browser_verify_value`), plus `network`, `storage`, `config` and `devtools` groups. The README's `--caps` flag text lists only vision/pdf/devtools, which is an internal inconsistency — [Playwright MCP README](https://github.com/microsoft/playwright-mcp)

**HyperAgent (Hyperbrowser) / Steel**
- HyperAgent is open-source and built on Playwright. It has `page.perform()` for single granular actions plus a higher-level task mode, action caching for deterministic replay, and acts as an MCP client for custom tools — [HyperAgent GitHub](https://github.com/hyperbrowserai/HyperAgent); [YC launch](https://www.ycombinator.com/launches/NO8-hyperagent-open-source-ai-browser-automation-framework)
- Steel is browser infrastructure, not an agent framework. It is a self-hostable runtime for Playwright/Puppeteer/Selenium/Browser Use/Stagehand/any CDP agent, with Profiles, Credentials, Files and Agent Logs. This comes from a competitor's (Notte) comparison page, so treat it with caution — [Notte answers: Hyperbrowser vs Steel](https://ai.notte.cc/answers/hyperbrowser-vs-steel)

### Inferences
- For "extract N products and compare" tasks, the tested pattern is: one schema-typed extraction call per listing page (Browser Use `extract` with `output_schema`, Stagehand `extract` with Zod, Skyvern Data Extraction), followed by in-code or in-LLM comparison. Browser Use 0.x adds a cheap pre-step (`find_elements` to count product cards, `search_page` for prices) that needs no LLM.
- Browser Use's move to Python (1.0) suggests that, for lists, letting the model write a parser (for example BeautifulSoup over HTML from `js`/`http_get`) beats calling an extraction tool for each item.
- Playwright MCP has no extraction tool. List extraction has to go through `browser_snapshot` (with `target`/`depth`) or `browser_evaluate` returning JSON.

### Gaps
- Exact Agent-E skill function names (for example `get_dom_with_content_type`, `bulk_enter_text`) could not be confirmed from the paper text. They are in Figure 4 and the repo, which was not fetched.
- Skyvern's low-level action list (CLICK, INPUT_TEXT, SELECT_OPTION, etc.) was not fetched from source.
- The defaults for Browser Use 0.x `search_page` and `find_elements` `max_results` live in `tools/views.py`, which was not read.
- No release date for Browser Use 1.0 was found in the docs.

## How does each find the right element on a large page (hundreds of links) without overflowing the context?

### Takeaway
Three strategies dominate. (1) Index only interactive elements, show only the viewport, and mark new elements (Browser Use 0.x). (2) Trim the accessibility tree or scope it to a subtree, and use an LLM "observe" step to pick candidates (Stagehand `observe`/`ariaTree`, Playwright MCP `browser_snapshot` with `target`/`depth` plus `browser_find`). (3) Task-specific DOM distillation (Agent-E's `text_only` / `input_fields` / `all_fields`). Cheap non-LLM search tools (`search_page`, `find_elements`, `browser_find`) are the main trick for large pages.

### Cited Findings
- Browser Use 0.x state format: interactive elements are listed as `[index]<type>text</type>`, and only indexed elements are actionable. Tab indentation shows hierarchy. `*[` marks elements that are new since the last step. Non-bracketed text is non-interactive. The listing is viewport-oriented — [system_prompt.md @0.12.0](https://raw.githubusercontent.com/browser-use/browser-use/0.12.0/browser_use/agent/system_prompts/system_prompt.md)
- Browser Use 0.x prompt: "Use `search_page` and `find_elements` before scrolling or calling `extract`, since they're free." — [system_prompt.md @0.12.0](https://raw.githubusercontent.com/browser-use/browser-use/0.12.0/browser_use/agent/system_prompts/system_prompt.md)
- Browser Use 0.x `read_long_content` reads up to 50,000 chars. Larger content is split into 2,000-char chunks, ranked by 3–5 LLM-generated search terms, and handled page by page for PDFs — [service.py @0.12.0](https://raw.githubusercontent.com/browser-use/browser-use/0.12.0/browser_use/tools/service.py)
- Browser Use 1.0 drops `browser_use.dom`/`DomService` and the DOM tuning options. "The agent no longer picks one action per step from a DOM dump." Screenshots are taken on demand (`use_vision=True` is ignored; `use_vision=False` is kept) — [Migrating from 0.x](https://docs.browser-use.com/open-source/migrating.md)
- Stagehand uses "hybrid accessibility-tree trimming" to give agents only the page context they need — [Stagehand README](https://github.com/browserbase/stagehand). `observe()` accepts a `selector` that scopes the accessibility snapshot to a container — [Stagehand caching docs](https://docs.stagehand.dev/v3/best-practices/caching)
- Playwright MCP: actions reference elements by a `target` ref from the accessibility snapshot (or a unique selector). `browser_snapshot` supports `depth`, `target` (scope to one element) and `filename` (write to file instead of returning inline). `browser_find` searches the snapshot by text or regex with `maxResults`, and is documented as cheaper than a full snapshot when you only need one ref. No incremental or diff snapshots are documented — [Playwright MCP README](https://github.com/microsoft/playwright-mcp)
- Playwright MCP token flags: `--snapshot-mode full|none`, `--snapshot-boxes` (off by default), `--image-responses allow|omit|only`, `--caps` (a smaller tool list), `--mobile` (lighter pages "save tokens"), `--console-level`, and `--output-dir`/`--output-max-size`. The README recommends the Playwright CLI + SKILLs for coding agents, to avoid loading large tool schemas and verbose accessibility trees — [Playwright MCP README](https://github.com/microsoft/playwright-mcp)
- Agent-E DOM distillation: `text_only` (reading/summarizing), `input_fields` (search/form inputs), `all_fields` (all interactive elements). Denoising keeps parent-child relationships, and each element gets an injected `mmid` identifier attribute — [Agent-E arXiv](https://arxiv.org/html/2407.13032)
- Agent-E's planner only gets summaries from the navigator, "insulated from noisy page and DOM details", and the navigator is freshly instantiated for each sub-task with no prior step history — [Agent-E arXiv](https://arxiv.org/html/2407.13032)
- Skyvern: each action sends a multimodal LLM an annotated screenshot plus a structured description of interactable elements. The format was originally JSON and was later compared against HTML and markdown. This comes from a related-post excerpt on the Skyvern blog — [Skyvern 2.0 blog](https://www.skyvern.com/blog/skyvern-2-0-state-of-the-art-web-navigation-with-85-8-on-webvoyager-eval/). The README says Skyvern uses vision LLMs instead of predefined XPaths — [Skyvern README](https://github.com/Skyvern-AI/skyvern)
- Notte turns pages into "actionable observations and clean markdown". `observe()` returns an action space, and `scrape(only_main_content=True)` returns main-content markdown — [Notte README](https://github.com/nottelabs/notte)
- HyperAgent syncs CDP state with the DOM structure used for LLM reasoning, and handles cross-origin (OOPIF) frames with a multi-map. This is from secondary/doc summaries — [HyperAgent GitHub](https://github.com/hyperbrowserai/HyperAgent)

### Inferences
- On an Amazon-style product page, the low-token pattern is: (a) use a free text/regex search (`search_page`, `browser_find`) or a scoped snapshot (`target`, `selector`) to locate the buy box, price or variant dropdown; then (b) act by ref or index. Avoid dumping the whole tree.
- Agent-E's content-type sensing (ask only for `input_fields` when you want to search) is a simple trick that any custom agent can copy.

### Gaps
- Browser Use 0.x DOM-serializer internals (paint-order filtering, element caps, "pixels above/below" markers) were not confirmed from source in this session.
- Stagehand's exact tree-trimming rules and v3 CDP-native internals are not documented in the pages fetched.
- Skyvern's current element serialization format (JSON vs HTML vs markdown) and any element caps were not found in primary docs.

## What separate roles (planner, navigator, validator/judge) exist, and how is success validated before claiming done?

### Takeaway
Skyvern 2.0 (planner, actor, validator) and Agent-E (planner, browser navigation agent) are the explicit multi-agent designs, and both credit the extra roles with large gains. Browser Use moved the other way. 1.0 removed the planner and memory options, keeps an optional `judge`, and relies on a self-check prompt before `done`. Stagehand and Playwright MCP are single-loop or tool-only, with no built-in validator.

### Cited Findings
- **Skyvern 2.0 (blog dated Jan 16, 2025):** Skyvern 1.0 was a single prompt in a loop, scoring about 45% on WebVoyager, and struggled with multi-part goals (for example, wrong cart quantities). Adding a Planner, which splits the objective into goals and keeps working memory of completed and pending steps, raised it to about 68.7%. Adding a Validator, which checks whether each goal was actually achieved and reports errors to the planner for re-planning, reached 85.85%. The Actor's self-reported success "was not always accurate" because some clicks failed silently — [Skyvern 2.0 blog](https://www.skyvern.com/blog/skyvern-2-0-state-of-the-art-web-navigation-with-85-8-on-webvoyager-eval/)
- **Agent-E:** The planner breaks the task into sub-tasks and delegates them one at a time. It is prompted to add verification steps (ask the navigator for info or confirmation) and re-plans when results look wrong (for example, an over-narrow search). It can backtrack using the URLs it tracks. Built on AutoGen + Playwright — [Agent-E arXiv](https://arxiv.org/html/2407.13032)
- **Browser Use 0.x per-step self-evaluation:** The output fields are `thinking`, `evaluation_previous_goal`, `memory` (1–3 sentences), `next_goal`, `current_plan_item`, `plan_update` and `action`. The screenshot (`<browser_vision>`) is "ground truth" and the agent must "never assume an action succeeded" — [system_prompt.md @0.12.0](https://raw.githubusercontent.com/browser-use/browser-use/0.12.0/browser_use/agent/system_prompts/system_prompt.md)
- **Browser Use 0.x pre-done checklist:** Re-read the request, list every requirement, and confirm the item count, applied filters, format, and that forms or files were actually completed. If anything is unmet or unverifiable, set `success=false`. `done` must be the only action in its step. Reassess at 75% of the step budget — [system_prompt.md @0.12.0](https://raw.githubusercontent.com/browser-use/browser-use/0.12.0/browser_use/agent/system_prompts/system_prompt.md)
- **Browser Use 1.0:** The planner was removed ("each step is one Python cell"). The memory options `enable_memory`/`memory_config` were dropped. `use_judge`/`ground_truth` became `judge`/`judge_context`, with the verdict in `result.judgement`. `judge_llm` was removed — [Migrating from 0.x](https://docs.browser-use.com/open-source/migrating.md)
- **Browser Use 1.0 budget end:** When budgets (`max_steps=100`, `timeout=1700` shown) run out, a "delivery-only turn" tells the agent to hand in what it has and set `success=False` if the task is unfinished. `checkpoint(filename, value, partial=True)` saves partial results — [Long tasks docs](https://docs.browser-use.com/open-source/long-tasks.md)
- **Browser Use evaluation judge:** For the Online-Mind2Web run, Browser Use replaced the screenshot-based judge with an agentic judge built on the Claude Agent SDK, which they say was aligned with human judges — [Browser Use: Online-Mind2Web post](https://browser-use.com/posts/online-mind2web-benchmark)
- **Stagehand `agent()`:** `maxSteps` defaults to 20. The result has `success` and `completed`, and a `close` action carries `taskCompleted`. The docs do not describe a separate validator — [Stagehand docs: agent](https://docs.stagehand.dev/v3/basics/agent)
- **Skyvern** has a Validation workflow block and `page.validate` in its SDK — [Skyvern README](https://github.com/Skyvern-AI/skyvern)
- **Playwright MCP** has opt-in `testing` assertions (`browser_verify_text_visible`, `browser_verify_list_visible`, `browser_verify_value`, `browser_verify_element_visible`) that an agent can use as explicit checks — [Playwright MCP README](https://github.com/microsoft/playwright-mcp)

### Inferences
- The best-documented ablation is Skyvern's. Planner plus validator roughly doubled success (45% to 68.7% to 85.85%), and the validator alone added about 17 points. That makes a separate "did it really happen?" check the highest-value addition for silent-failure clicks such as add-to-cart.
- Browser Use reached its top score without a separate planner. It relies on a strong self-check prompt plus an external judge, which suggests a stronger LLM plus code execution can replace explicit planner roles.

### Gaps
- The Skyvern validator's exact inputs (screenshot vs DOM) and prompts are not described in the blog.
- No primary description was found of how Stagehand decides `taskCompleted`.

## What tricks reduce steps and tokens on e-commerce tasks (memory, caching, replay, compression)?

### Takeaway
The main levers are: (1) chain several actions per LLM call (Browser Use 0.x); (2) use free non-LLM search and query tools before reading the page; (3) cache or replay successful runs as deterministic code (Stagehand `cacheDir` and Browserbase server cache, Skyvern `run_with="code"`, HyperAgent action cache); (4) compact history and drop old screenshots (Browser Use 1.0); (5) use compact output formats (Browser Use: TSV over JSON saves about 40% of tokens).

### Cited Findings
- **Browser Use 0.x multi-action steps:** Up to `{max_actions}` actions run in sequence per step. If the page changes, the remaining actions are skipped. Page-changing actions (`navigate`, `search`, `go_back`, `switch`, `evaluate`) go last. Safe to chain: `input`, `scroll`, `find_text`, `extract`, `search_page`. "Apply filters before browsing results". Do not retry a failing action or a 403-blocked URL more than 2–3 times. A `todo.md` plan file and `results.md` are used for long tasks, but not for tasks under 10 steps — [system_prompt.md @0.12.0](https://raw.githubusercontent.com/browser-use/browser-use/0.12.0/browser_use/agent/system_prompts/system_prompt.md)
- **Browser Use 0.x memory truncation:** Memory keeps only the first 100 chars of the `done` text, about 1,000 chars of `read_file`, and under 10,000 chars of `evaluate` results — [service.py @0.12.0](https://raw.githubusercontent.com/browser-use/browser-use/0.12.0/browser_use/tools/service.py)
- **Browser Use 1.0 context compaction:** Compaction is server-side on the Gateway/OpenAI Responses API above 150k tokens. Otherwise it triggers at 75% of `max_context_chars` (default 4 chars per token of the window, or 240k) or 65% of the model window. Older turns are replaced by a summary checkpoint, while the original task and the last two steps stay verbatim. An evidence archive keeps the raw history. Once more than 20 tool results contain images, images are stripped from all but the newest 2. Each Python cell is limited to 120s. Failed cells are not auto-retried, and the model reads the error. Provider errors are retried once — [Long tasks docs](https://docs.browser-use.com/open-source/long-tasks.md)
- **Browser Use harness tricks (Mar 2026):** Python code execution was "the biggest improvement". Other tricks were TSV over JSON (about 40% fewer tokens), fixing "hundreds of edge cases" through an auto-research loop run by Claude Code, and stealth browser infrastructure — [Browser Use: Online-Mind2Web post](https://browser-use.com/posts/online-mind2web-benchmark)
- **Stagehand caching:** (a) Browserbase server cache, enabled per project via support. The key is instruction + page content + options. `act()` returns `cacheStatus` `"HIT"`/`"MISS"`, and it can be turned off with `serverCache: false`. (b) Local `cacheDir` works in LOCAL or BROWSERBASE mode: the first run records each action and agent step, and later runs replay with no LLM calls. Variables are keyed by name, not value. Agent cache keys are instruction + start URL + execution options + agent config. Guidance: use one `cacheDir` per workflow, commit it for CI, clear it after DOM changes, and keep instructions short and anchored to visible labels — [Stagehand caching docs](https://docs.stagehand.dev/v3/best-practices/caching). `act`/`observe`/`extract` "refresh how an action happens" when the site changes (self-healing) — [Stagehand README](https://github.com/browserbase/stagehand)
- **Skyvern code caching:** After a successful run, Skyvern records the actions and generates reusable code. Use `run_with="agent"` the first time and `run_with="code"` to replay. AI Fallback is on by default: if the cached code fails, it falls back to the agent and regenerates. Caching is per block, while conditional, wait and code blocks always run live. The docs disagree on whether `engine="skyvern-2.0"` is required or default — [Skyvern code caching docs](https://skyvern.com/docs/developers/features/code-caching). A "2.7x cheaper, 2.3x faster on subsequent runs" claim appears only in third-party launch listings — [hunted.space listing](https://hunted.space/product/skyvern/launches/skyvern-8fa4b8bf-0253-46d3-b4bc-63bd0a92f2c1)
- **Agent-E** recommends caching and converting successful runs into classical workflows, and denoising payloads — [Agent-E arXiv](https://arxiv.org/html/2407.13032)
- **HyperAgent** caches actions for deterministic replay — [HyperAgent GitHub](https://github.com/hyperbrowserai/HyperAgent)
- **Playwright MCP:** use `--image-responses omit`, `--snapshot-mode none`, `--mobile`, fewer `--caps`, `filename` outputs, and `browser_find` over full snapshots — [Playwright MCP README](https://github.com/microsoft/playwright-mcp)
- **Stagehand `observe`** returns selectors that can be reused in plain Playwright with no further LLM calls — [Stagehand README](https://github.com/browserbase/stagehand)

### Inferences
- E-commerce tasks are repetitive (search box, filters, sort, product grid). Record-then-replay (Stagehand/Skyvern/HyperAgent) plus "apply filters first, then one schema extraction of the grid" is likely to give the biggest step savings.
- Typing into the search box and pressing Enter in one chained step, or navigating straight to a search-results URL, avoids several LLM turns. This follows from Browser Use's chaining rules but is not benchmarked.

### Gaps
- No primary token or cost-per-task numbers were found for Stagehand v3, Skyvern 2.0 or Browser Use 1.0.
- Skyvern's generated-script internals are undocumented.

## Published benchmark claims (with dates and caveats)

### Takeaway
Nearly all headline numbers are self-reported, with vendor-run judges. WebVoyager is widely considered inflated. Online-Mind2Web (300 tasks across 136 sites) is now the reference, and Browser Use claims 97% there (Mar 2026, `bu-max`).

### Cited Findings
- **Browser Use:** 89.1% on WebVoyager (586 tasks) in the "SOTA technical report" (Dec 2024 per its post timeline; date not re-verified this session) — [Browser Use SOTA report](https://browser-use.com/posts/sota-technical-report). 97% on Online-Mind2Web, "Self-Reported, March 2026" (post dated Mar 25, 2026), using Browser Use Cloud `bu-max` on 300 tasks (83 easy / 143 medium / 74 hard) with "No tasks removed". The judge was agentic, built on the Claude Agent SDK — [Browser Use: Online-Mind2Web post](https://browser-use.com/posts/online-mind2web-benchmark)
- **Competitor Online-Mind2Web figures listed by Browser Use (Mar 2026):** GPT-5.4 Native CU 93% (unverifiable), UI-TARS-2 88%, ABP + Claude Opus 4.6 86%, OpenAGI Lux 84%, TinyFish 81%, Yutori Navigator 79%, ChatGPT Atlas Agent Mode 71%, Gemini CUA 69%, Stagehand (Gemini 2.5 CU) 65%, OpenAI Operator 61%, Claude Sonnet 4.0 CU 61%, Stagehand (Sonnet 4.5) 55% — [Browser Use: Online-Mind2Web post](https://browser-use.com/posts/online-mind2web-benchmark)
- **Independent checks:** On Princeton HAL's Online-Mind2Web leaderboard, Browser Use with Claude Sonnet 4 (May 2025) scored 40.00% — [HAL: Browser-Use](https://hal.cs.princeton.edu/agent/Browser-Use). Notte's open evaluation found Browser Use at 77.3% self-reported and 60.2% LLM-verified, versus the stated 89% WebVoyager. Notte is a competitor — [Notte open-operator-evals](https://github.com/nottelabs/open-operator-evals); [dev.to summary](https://dev.to/andreanotte/opensource-web-agent-outclasses-browser-use-ne1)
- **Online-Mind2Web paper:** "An Illusion of Progress?" argues WebVoyager results are inflated and introduces 300 tasks across 136 websites. Tasks are replaced regularly, so scores from different periods are not directly comparable — [arXiv 2504.01382](https://arxiv.org/html/2504.01382v4); [Online-Mind2Web repo](https://github.com/OSU-NLP-Group/Online-Mind2Web)
- **Skyvern 2.0:** 85.85% on WebVoyager (blog Jan 16, 2025, updated Sep 30, 2026). It ran on Skyvern Cloud async browsers with GPT-4o/GPT-4o-mini. Eight tasks were removed as invalid, and flight/hotel dates were updated. Results are public at eval.skyvern.com. The authors note WebVoyager covers only 15 hand-picked sites — [Skyvern 2.0 blog](https://www.skyvern.com/blog/skyvern-2-0-state-of-the-art-web-navigation-with-85-8-on-webvoyager-eval/). 64.4% on WebBench, described as best on WRITE tasks (date not stated) — [Skyvern README](https://github.com/Skyvern-AI/skyvern)
- **Agent-E (Jul 2024):** 73.2% on WebVoyager (73.1% in the table) with GPT-4-Turbo and human graders. That is about 20 points above WILBUR (text-only) and about 16 above the WebVoyager multimodal agent. Best site WolframAlpha 95.7%, worst Booking 27.3%. About 25 LLM calls and about 150s per successful task — [Agent-E arXiv](https://arxiv.org/html/2407.13032)
- **Stagehand:** the README's only claim is "2x faster execution than Playwright cloud equivalent browsers" on Browserbase, with no methodology — [Stagehand README](https://github.com/browserbase/stagehand). Third-party Online-Mind2Web figures for Stagehand are listed above.
- **Notte:** the current README makes no benchmark claims — [Notte README](https://github.com/nottelabs/notte)

### Inferences
- Booking-style multi-filter sites are the hardest category (Agent-E 27.3%). That fits e-commerce filter- and date-heavy flows being where validators and replay pay off most.
- Treat any 85–97% figure as an upper bound: they are self-judged, with removed or edited tasks on WebVoyager.

### Gaps
- No primary benchmark numbers were found for Playwright MCP, HyperAgent, Hyperbrowser or Steel.
- The exact date of Browser Use's WebVoyager 89.1% report was not re-verified this session.
